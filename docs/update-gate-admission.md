# Daemon/CLI update admission (G2)

Voice availability and update authorization deliberately differ. AGENTS.md says **"a fix that loses my words is worse than the bug"**. A missing gate must not disable dictation. Daemon/standalone/stdio startup and first voice admission exclusively create an absent OPEN generation-0 record and private 0700 `<gatePath>.admissions` directory under G1's lock. Creation never replaces an existing record or repairs a malformed one.

For malformed/contradictory existing gate data, voice remains available: it registers its operation, emits a loud fixed diagnostic, and writes `<gatePath>.voice-diag.json`. The original gate bytes stay intact. Updater requests/acknowledgements refuse UNKNOWN for missing, malformed, contradictory or diagnostic-marked evidence; updater calls never bootstrap. A verified recovery must reconcile evidence and clear diagnostics. Valid DRAINING/PREPARED/COMMITTED gates still refuse new voice work with UPDATE_BUSY.

Admissions retry lock contention with bounded exponential backoff (1.5 seconds); exhausted contention is UPDATE_GATE_LOCK_TIMEOUT, not a closed-gate report. Release retries only its own record with exponential backoff for the process lifetime. Ownership mismatches return failure under the lock rather than throwing and orphaning it. Non-contention release failures preserve the record for recovery. No code reaps another owner's lock or registration.

Ledger records are 0600 JSON `{token,pid,incarnation,generation}` (generation null for degraded voice). Write-and-rename provides cross-process visibility; ledger registration/release never does F_FULLFSYNC on the capture path. Authoritative gate-state transitions and exclusive bootstrap reuse G1's full fsync/rename/parent-fsync/F_FULLFSYNC primitive. The lock remains G1's nonrecursive mkdir. The preload forces every path into its run root.

Only an operation's own archives can delay its admission release. Transient failed writes are retryable and successful retries release the original waiters. A deterministic dropped write affects its own archive, not future/unrelated operations. Physical exit uncertainty still retains admission. Ask spans prompt→capture→answer; queued selections carry required admission scopes through preparation, start and cancellation. Stop/Cancel, mute, silent think, paused replay/restart and admitted Next remain usable during drain. Historical replay/readback is new work and is gated before acknowledgement.

Trusted updater API: `updateVoiceGate(REQUEST|CANCEL)`, `acknowledgeVoiceDrain(lease, proof)`, and `updateVoiceGate(PREPARE|COMMIT, proof)`. The old storage `applyUpdateGateCommand` routes to this same admission-aware path; there is no second exported command implementation that skips the ledger. Prepare/commit recheck the empty ledger and current synchronous participant/target proof under the lock. Mutate only on APPLIED COMMIT; UNCHANGED never repeats installation. Missing proof refuses UNKNOWN; persisted preparation is insufficient.

G3/G4 must supply live native/daemon identity, pending-handoff, archive-durability, competing-owner and staged-target probes. Never accept those assertions from unauthenticated clients. Drain never writes Stop/Cancel signals.

Surface sweep: entry points cover MCP speak/ask/converse, raw socket speech/record/retranscription/previews, CLI fallback and exported media boundaries. Shared handlers cover daemon/standalone/stdio; admission precedes backend selection. Focused tests exercise fresh/corrupt state, lock races, retries, teardown, archive isolation and controls. Touched-area suites cover existing capture/playback/ingress contracts. Native F5/History/quit, Swift/Bun runtime parity, installer/cask integration and installed-app/agent proof remain lead/G3/G4 qualification. Harness latency is not real-app onset proof. No app build/install or live gate/socket operation was performed in this lane.
