## What changed from TLA3

The October 20 model treated QUEUE1 as a proposal, replaced the user chain on main, and assumed stale receipts were ignored. This extracts and refines its QUEUE1 actions against the implemented `SelectionReadQueue`: append/replace, scoped Next, all settlement outcomes, F5 suspension, explicit Stop, direct ownership and published counts. The older priority-player, parked-audio and capture-admission models are **not** revalidated or silently imported here. Source anchors and their sync SHA are in [coverage.json](coverage.json).

Four fresh request IDs, two pending slots and eight operations are explored; four IDs make overflow reachable. Every request deliberately has identical text and text hash in the real-code replay. Successful starts return immediately without audio or archive context. Each synchronous start also delivers the former owner's stopped receipt before returning, exercising ownership-before-preemption. Failures of the start callback and async preparation are outside this model.

TLC checks unique ownership/starts, count publication, stale Next rejection and Stop clearing the chain. `check.py` exports the current reachable graph, finds a shortest prefix for each state, and replays **each outgoing edge** from that prefix against the actual production class. It compares start IDs, pending count, published owner/count and return value. This is bounded observational conformance, not every possible trace, a refinement proof, real player execution or macOS acceptance. The ordinary Bun suite skips the generated-corpus test; `check.sh` makes it mandatory.

## Expected counterexamples

`StaleNext.cfg` deliberately removes Next ownership validation. Its shortest trace is an idle queue receiving Next for request 1: it returns stopped instead of stale. With a live chain, the same missing guard lets an old Next skip the new owner. `Current.cfg` requires `StaleCannotAdvance`; the broken config must fail that exact invariant, not merely exit with any error.

`StopLeaves.cfg` deliberately retains pending items in Clear. Submit A, append B, then Stop leaves B queued and violates `StopClearsQueues`. This is checker sensitivity, not evidence that the current source has that defect. The real-code experiments below are the separate source-fidelity check.

`History.cfg` checks the current nine-state relation in `src/speech-state.ts:4-10,25-34` for four operations. `FirstAcceptedTerminalImmutable` freezes both the first terminal state and the accepted-transition count; even a repeated terminal cannot add another accepted edge. The conformance harness executes the real transition function and checks state plus transition count. It does not model producer routes, retries, durable writes or reasons/timings. Existing producer-route fixtures and runtime code remain unchanged. `MutableTerminal.cfg` accepts later terminal transitions and must violate this invariant: accept stopped, then accept completed, overwriting the first terminal.

## Live bug disposition

**1. Same text playing/queued breaks the queue — current Swift admission counterexample; recording correlation unproven.** The backend model and identical-text conformance pass: this class uses request IDs and never compares text hashes. Swift explicitly compares the latest submitted selection and the playing selection in `flow-bar/Sources/VoiceBarUI/VoiceState.swift:1262-1282`, then calls `stopSelectionRead()` on equality before enqueueing. Fresh selections use a UUID at line 1303. `AdmissionFinding.cfg` now fails `NonemptySelectionDoesNotStop` on this current-code decision; this is not an injected model defect. See the admission evidence below. No runtime fix is included.

**2. Pause/Play/Next/Stop “nothing sticks” — partly covered, live cause unproven.** Backend Next, Stop, stale settlements and F5 suspension conform within the bound. Pause/Play operate on the separate player lifecycle: `src/socket-handlers.ts:190-200` routes scoped controls to `pausePlayback`/`resumePlayback`; `src/tts.ts:1292-1401` parks/releases audio and fences generations. Those async player, socket, ack and Swift UI states are absent here. No installed control interaction was performed, so this report cannot identify or clear the live cause.

**3. Replay after completion loses markdown — outside queue ownership.** Fresh selection ingress projects structured display in `src/socket-handlers.ts:219-235`. The idle replay branch at `src/socket-handlers.ts:324-335` instead retrieves history and supplies text, voice and timings; it supplies no structured display. The separate retained-readback path preserves more metadata (`src/tts.ts:2154-2188`). This is a concrete source-path mismatch to investigate, not a formatting reproduction or fix; the model has neither display payload nor renderer.

**4. History stuck Playing/PID reuse — outside in-memory queue state.** `src/speech-archive-recovery-worker.ts:43-47` trusts numeric-PID liveness via `process.kill(pid, 0)` and skips recovery when that PID exists, without process-start identity. `flow-bar/Sources/VoiceBarUI/SettingsSpeechHistoryArchive.swift:101-118` renders the stored playing state. A reused PID can therefore evade that recovery branch, but no private entry or restarted daemon was tested. Durable writer/recovery ownership needs its own model and real recovery regression; a queue pass provides no History proof.

The brief's optional B-queue QA findings file was absent on the resume pass too. Neither named recording was inspected by this worker. An event-by-event account remains unavailable. ## Swift admission: finding and proposed policy

`Admission.tla` checks one admission decision over three canonical text classes: latest submitted input, playing input and one earlier queued input are each absent or a class; the selected input is nonempty. `Snapshot` enumerates arbitrary known-text snapshots, not reachable Swift lifecycle traces. `Admit` is the synchronous Stop guard after capture completion. Capture callbacks, hash/normalization correctness, unknown external text, press-time fallbacks, clipboard refusals, full queues and receipt races are excluded. There are 192 decisions and 257 states. `AdmissionCurrent.cfg` checks the current decision; `AdmissionFinding.cfg` preserves its failure of the proposed nonempty-input property; `AdmissionProposed.cfg` passes the distinct-request policy **only in the model**.

TLC's shortest finding: A has been submitted and is still awaiting its speaking receipt (`latest=A`, `playing=none`); select A again; Swift sends Stop instead of creating a new request. Additional decisions in the checked graph: with A playing and B latest, selecting either A or B stops the entire chain. With A playing, B queued earlier and C latest, selecting B does not match either comparator and is submitted again. Queue equality therefore depends on position, not content alone. Source Stop invalidates all selection identities, clears the local queue mirror and sends `stop` (`VoiceState.swift:1118-1135`); backend Clear is separately covered above. These paths can explain queue disappearance in the recordings only if those selections and timings occurred. A duplicate of an earlier queued item, an active-capture double press (`VoiceState.swift:1208-1211`), or a later receipt/control failure needs separate evidence; same-selection equality alone does not explain every event or bug 2.

`admission_source.py` extracts and evaluates the actual Swift Stop Boolean expression over all 192 snapshots. Its sameSelection/samePlaying flags are a documented projection of lines 1262-1279; it does **not** execute Swift or validate that flag computation. A scratch edit removed `|| samePlaying` from the real guard at line 1280. The current TLC configs still passed, then the source check failed for latest=B, playing=A, input=A. The Swift file was restored byte-for-byte (SHA256 `3b10a5f6d377d70716eb6860fb64e8d646527ca5cd873e9e176d2b0a7de86f24`). No Swift build or XCTest was run under the host-pressure restriction. Existing Swift tests explicitly expect same-selection Stop (`flow-bar/Tests/VoiceBarUITests/SpeakSelectionTests.swift:871-899`); they must change with the product contract, not be silently weakened here.

Proposed separate fix: a successful nonempty Option+F5 capture always gets a fresh request identity, even when its content matches the playing/latest/earlier queued input; explicit Stop (and the existing empty ordinary-selection gesture) clears the chain. Remove sameSelection/samePlaying from this Stop admission condition, then update the Swift behavior tests and run installed Option+F5 queue/control acceptance with the real agents. The source guard edit is tiny, but it changes a deliberate old UX contract and its existing tests, so this model PR does not ship it. Capture-in-flight cancellation remains a separate gesture. The proposed config establishes only that a nonempty duplicate cannot emit implicit Stop, not queue admission success, liveness or a deployed repair.

**Prosody abort hang (separate lane):** the lead reported `src/__tests__/prosody-schedule.test.ts:134` ran for 23.5 hours at 97% CPU. That test awaits `scheduler.settled()` through `FakeClock.until`, whose microtask/timer loop is not represented here. These queue/terminal safety models contain no scheduler tasks, virtual clock, event-loop fairness or abort/drain liveness. They do not explain the hang or prove its repair; that test and its scheduler remain unchanged.

## API constraints for NL T3 alignment

**Current verified properties:** Next and settlement are fenced by request ownership; Stop forgets all queued work; identical text/hash with distinct accepted request IDs stays distinct in the backend; a History record's first accepted terminal status is immutable. Preserve the existing History producer-route fixtures. These checks do not transfer VoiceLayer's admission, microphone, UI or History ownership to an engine.

**Future contract properties, not established by these models:** fence every attempt and playback generation so late results cannot commit or revive cancelled work; check cancellation before commit (client abort is not confirmed backend drain); retain the Stop and accepted-request identity guarantees across the adapter; keep first accepted History terminals immutable across producers and retries; carry the original structured display through completed-read replay. Current Swift same-text-means-Stop ingress and idle replay metadata loss remain findings above, not claims that those future properties hold today. No clone adapter or NarrationLayer migration is implemented here.

| Future API invariant | Required observable behavior | Current evidence boundary |
| --- | --- | --- |
| Generation fencing | Every start, control, completion and commit carries request/attempt/generation identity; reject receipts for older ownership. | Queue request fencing checked; player/engine generations excluded. |
| Cancel before commit | After cancellation, a late synthesis result is disposed without playback or a successful terminal commit; expose backend drain separately from abort acknowledgement. | No synthesis/commit/drain liveness in these specs. |
| Stop clears queued work | Explicit Stop removes pending requests and fences late results so nothing restarts the stopped chain. | Synchronous Clear checked; physical teardown and late engine results excluded. |
| Same-text identity | Distinct accepted invocations remain distinct even when text/hash matches; retries retain a separate idempotency identity. | Backend distinct IDs checked; Swift admission currently conflicts with proposed nonempty policy. |
| First accepted History terminal | Once a producer accepts completed/stopped/cancelled/failed/interrupted, later producers/retries cannot replace it or append another accepted terminal. | Pure transition relation checked; producer routes, persistence and recovery identity excluded. Preserve all existing producer-route fixtures. |
| Structured replay | Replaying a completed read retains the original structured display and timing association, independent of cleaned speech text. | Idle replay currently omits structured display; no renderer or payload model. |
