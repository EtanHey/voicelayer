# Speech queue verification

Status: bounded backend verification; **the four installed-app bugs remain unresolved**. No product fix, install, microphone, speaker, live socket or private archive access is part of this change.

Run `timeout -s TERM -k 10 900 formal/speech-queue/check.sh` from the repository. Requires Python 3, Bun dependencies (`bun install --frozen-lockfile`), GNU `timeout`, Java and `~/.local/bin/tlc` (override with `TLC`). Tested with the existing tla2tools-1.7.4.jar launcher, which reports TLC2 2.19, revision `5a47802`. Logs, graph and generated replay corpus stay in a unique `.build.noindex/formal-speech-queue/run-*` directory; only the latest three runs are retained. Python runs with bytecode disabled. Each phase streams stdout/stderr directly into its log. The supervisor owns each child process group, forwards SIGTERM/SIGINT, kills the group and reaps the child on every phase exit, and limits each phase to the remaining 880-second whole-run budget (TLC also has a 90-second cap). An unexpected TLC result, parse failure, timeout or real-code mismatch exits nonzero. The outer TERM deadline allows cleanup before its KILL fallback; an external SIGKILL cannot run Python cleanup. The requested hard-KILL wrapper is used once for the successful R1 validation, whose 880-second internal deadline precedes the outer 900-second cap.

## What changed from TLA3

The October 20 model treated QUEUE1 as a proposal, replaced the user chain on main, and assumed stale receipts were ignored. This extracts and refines its QUEUE1 actions against the implemented `SelectionReadQueue`: append/replace, scoped Next, all settlement outcomes, F5 suspension, explicit Stop, direct ownership and published counts. The older priority-player, parked-audio and capture-admission models are **not** revalidated or silently imported here. Source anchors and their sync SHA are in [coverage.json](coverage.json).

Four fresh request IDs, two pending slots and eight operations are explored; four IDs make overflow reachable. Every request deliberately has identical text and text hash in the real-code replay. Successful starts return immediately without audio or archive context. Each synchronous start also delivers the former owner's stopped receipt before returning, exercising ownership-before-preemption. Failures of the start callback and async preparation are outside this model.

TLC checks unique ownership/starts, count publication, stale Next rejection and Stop clearing the chain. `check.py` exports the current reachable graph, finds a shortest prefix for each state, and replays **each outgoing edge** from that prefix against the actual production class. It compares start IDs, pending count, published owner/count and return value. This is bounded observational conformance, not every possible trace, a refinement proof, real player execution or macOS acceptance. The ordinary Bun suite skips the generated-corpus test; `check.sh` makes it mandatory.

## Expected counterexamples

`StaleNext.cfg` deliberately removes Next ownership validation. Its shortest trace is an idle queue receiving Next for request 1: it returns stopped instead of stale. With a live chain, the same missing guard lets an old Next skip the new owner. `Current.cfg` requires `StaleCannotAdvance`; the broken config must fail that exact invariant, not merely exit with any error.

`StaleClear.cfg` independently mutates the ignored stale-Next branch to `Clear(q)` while still returning `stale`. `StaleCannotAdvance` now records a violation from the actual pre/post queue record and returned result, rather than the selected guard branch. Its shortest counterexample is submit A, then stale Next(B): the queue owner changes to none even though the answer is stale. The same mutation passed the old invariant (9,595 states); that vacuous pass is preserved as a failed sensitivity check in the R1 receipt below. `StopClearsQueues` is still structural for the current Clear definition, so its sensitivity control and real-code conformance matter; TLC outcomes are not independent product guarantees.

`StopLeaves.cfg` deliberately retains pending items in Clear. Submit A, append B, then Stop leaves B queued and violates `StopClearsQueues`. This is checker sensitivity, not evidence that the current source has that defect. The real-code experiments below are the separate source-fidelity check.

`History.cfg` checks the current nine-state relation in `src/speech-state.ts:4-10,25-34` for four operations. `FirstAcceptedTerminalImmutable` freezes both the first terminal state and the accepted-transition count; even a repeated terminal cannot add another accepted edge. The conformance harness executes the real transition function and checks state plus transition count. It does not model producer routes, retries, durable writes or reasons/timings. Existing producer-route fixtures and runtime code remain unchanged. `MutableTerminal.cfg` accepts later terminal transitions and must violate this invariant: accept stopped, then accept completed, overwriting the first terminal.

## Swift admission: finding and proposed policy

`Admission.tla` checks one admission decision over three canonical text classes: latest submitted input, playing input and one earlier queued input are each absent or a class; the selected input is nonempty. `Snapshot` enumerates arbitrary known-text snapshots, not reachable Swift lifecycle traces. `Admit` is the synchronous Stop guard after capture completion. Capture callbacks, hash/normalization correctness, unknown external text, press-time fallbacks, clipboard refusals, full queues and receipt races are excluded. There are 192 decisions and 257 states. `AdmissionCurrent.cfg` checks the current decision; `AdmissionFinding.cfg` preserves its failure of the alternative nonempty-input property. `AdmissionOlderMatch.cfg` separately fails `EveryQueuedMatchStops` when playing/latest/older-queued are distinct and the older queued text is selected. That diagnostic property tests uniform Stop treatment of queued copies; it does not endorse clearing the queue on every duplicate. `AdmissionProposed.cfg` passes an unapproved distinct-request alternative **only in the model**, pending Etan's ruling. This pass is vacuous by construction: it never stops, and empty input is absent, so it does not test the remaining empty-selection Stop gesture.

TLC's shortest finding: A has been submitted and is still awaiting its speaking receipt (`latest=A`, `playing=none`); select A again; Swift sends Stop instead of creating a new request. Additional decisions in the checked graph: with A playing and B latest, selecting either A or B stops the entire chain. With A playing, B queued earlier and C latest, selecting B does not match either comparator and is submitted again. Queue equality therefore depends on position, not content alone. Source Stop invalidates all selection identities, clears the local queue mirror and sends `stop` (`VoiceState.swift:1118-1135`); backend Clear is separately covered above. QA B confirms these selection/position combinations in F-01/F-02. An active-capture double press (`VoiceState.swift:1208-1211`) and later receipt/control failures remain outside this decision model; equality alone does not explain bug 2.

`admission_source.py` extracts and evaluates the actual Swift Stop Boolean expression over all 192 snapshots. Its sameSelection/samePlaying flags are a documented projection of lines 1262-1279; it does **not** execute Swift or validate that flag computation. Only the Boolean expression at line 1280 is real-code checked. Lines 1262-1279 and `replacing` at 1218 are projected and unverified: changing the nil check, hash branch, or comparison precedence can leave this check green. Q1 owns XCTest admission conformance; this lane does not claim it. A scratch edit removed `|| samePlaying` from the real guard at line 1280. The current TLC configs still passed, then the source check failed for latest=B, playing=A, input=A. The Swift file was restored byte-for-byte (SHA256 `3b10a5f6d377d70716eb6860fb64e8d646527ca5cd873e9e176d2b0a7de86f24`). No Swift build or XCTest was run under the host-pressure restriction. Existing Swift tests explicitly expect same-selection Stop (`flow-bar/Tests/VoiceBarUITests/SpeakSelectionTests.swift:871-899`); they must change with the product contract, not be silently weakened here.

Unapproved policy alternative, awaiting Etan's ruling: a successful nonempty Option+F5 capture always gets a fresh request identity, even when its content matches the playing/latest/earlier queued input; explicit Stop (and the existing empty ordinary-selection gesture) clears the chain. Remove sameSelection/samePlaying from this Stop admission condition, then update the Swift behavior tests and run installed Option+F5 queue/control acceptance with the real agents. The source guard edit is tiny, but it changes Etan's 2026-10-16 same-selection=Stop contract (reaffirmed by the lead during this task), its current hotkey copy (`flow-bar/Sources/VoiceBarUI/VoiceBarHotkeyContract.swift:14-16`) and existing tests. Do not implement this alternative before that ruling; this PR contains no product fix. Capture-in-flight cancellation remains a separate gesture. The proposed config establishes only that a nonempty duplicate cannot emit implicit Stop, not queue admission success, liveness or a deployed repair.

## API constraints for NL T3 alignment

**Current verified properties:** Next and settlement are fenced by request ownership; explicit Stop (clear policy) forgets all queued work; F5 suspension retains it for Next; identical text/hash with distinct accepted request IDs stays distinct in the backend; a History record's first accepted terminal status is immutable under `transitionSpeech` (producer/recovery writers are excluded). Preserve the existing History producer-route fixtures. These checks do not transfer VoiceLayer's admission, microphone, UI or History ownership to an engine.

**Future contract properties, not established by these models:** fence every attempt and playback generation so late results cannot commit or revive cancelled work; check cancellation before commit (client abort is not confirmed backend drain); retain the Stop and accepted-request identity guarantees across the adapter; keep first accepted History terminals immutable across producers and retries; carry the original structured display through completed-read replay. Current Swift same-text-means-Stop ingress and idle replay metadata loss remain findings above, not claims that those future properties hold today. No clone adapter or NarrationLayer migration is implemented here.

| Future API invariant | Required observable behavior | Current evidence boundary |
| --- | --- | --- |
| Generation fencing | Every start, control, completion and commit carries request/attempt/generation identity; reject receipts for older ownership. | Queue request fencing checked; player/engine generations excluded. |
| Cancel before commit | After cancellation, a late synthesis result is disposed without playback or a successful terminal commit; expose backend drain separately from abort acknowledgement. | No synthesis/commit/drain liveness in these specs. |
| Stop clears queued work | Stop policy is explicit per gesture (clear vs retain). Explicit Stop removes pending requests and fences late results so nothing restarts the stopped chain. | Synchronous Clear checked; physical teardown and late engine results excluded. |
| Same-text identity | Distinct accepted invocations remain distinct even when text/hash matches; retries retain a separate idempotency identity. | Backend distinct IDs checked; Swift admission currently conflicts with proposed nonempty policy. |
| First accepted History terminal | Once a producer accepts completed/stopped/cancelled/failed/interrupted, later producers/retries cannot replace it or append another accepted terminal. | Pure transition relation checked; producer routes, persistence and recovery identity excluded. Preserve all existing producer-route fixtures. |
| Structured replay | Replaying a completed read retains the original structured display and timing association, independent of cleaned speech text. | Idle replay currently omits structured display; no renderer or payload model. |
